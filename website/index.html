Zero runtime dependencies · MIT licensed

Install Microsoft Store apps without signing in.

Ghostget is a winget-style CLI and Node.js library that fetches Microsoft's own signed web installer and runs it — the same thing the Get button on the Store website does, minus the account requirement.

The problem

winget's Store source needs an account. This doesn't.

winget install --source msstore <id> fails without a signed-in Microsoft Store account:

Verifying/Requesting package acquisition failed: no store account found

The Get button on the Store website doesn't need that. It downloads a small installer that Microsoft signs, and that installer asks the Store to do the rest. Ghostget automates exactly that: find the app, fetch Microsoft's own web installer, check its signature, run it. No account, no sign-in, no winget.

Features

Built to be trusted, scripted, and left alone

Every design choice favours safety and predictability over cleverness.

No account, ever

Uses the same public endpoints and web installer link Microsoft's own Store website hands to every visitor.

Verifies before it runs

The installer must carry a valid Authenticode signature from Microsoft Corporation, or it is deleted and never started.

winget-like commands

search, show, install, list, plus download, url and doctor.

Safe defaults

Refuses paid apps, never picks between look-alike apps for you, never elevates, never changes system settings.

Scriptable

--json everywhere, quiet stdout, stable exit codes. Built for CI and automation, not just interactive use.

Zero dependencies

Runs from npx, as a library, or as a single dependency-free PowerShell file on a PC without Node.js.

Under the hood

Four Microsoft services, one flow

Ghostget talks only to Microsoft's own hosts, over HTTPS, and never asks for credentials.

"terminal" ── search ──▶ storeedgefd.dsx.mp.microsoft.com (the Store app's own search API) 9N0DX20HK701 ─ details ─▶ displaycatalog.mp.microsoft.com (price, size, package family) ── GET ───▶ get.microsoft.com/installer/download/9N0DX20HK701 └─ a ~800 KB installer, signed by Microsoft verify signature ─▶ launch it ─▶ the Store finishes the install in its own window

Full protocol notes, evidence and edge cases are documented in How it works →

Ghostget vs. winget's msstore source

Same result, without the sign-in wall

❌ winget --source msstore

  • Fails with "no store account found" unless you're signed in
  • Signing in on shared/CI machines is often not possible
  • Opaque failures with little explanation

✅ ghostget

  • Uses the same web installer the Get button uses — no account needed
  • Works from `npx` on CI runners, fresh VMs, or a Windows box with no profile
  • Still verifies Microsoft's own Authenticode signature before running anything
Quick start

Three commands to your first install

Search

Find the app you want on the Microsoft Store.

npx ghostget search terminal

Inspect

Check publisher, price, size and package family before installing anything.

npx ghostget show 9N0DX20HK701

Install

Download, verify the Microsoft signature, and launch the Store's own installer.

npx ghostget install 9N0DX20HK701

Safety

Nothing runs unless Microsoft signed it

🔒 3 hosts, HTTPS only

Endpoint overrides must be https, or http on localhost.

✅ Signature required

Must report Valid and signer Microsoft Corporation, exactly. One flipped byte fails it.

🚫 No credentials

Never asks for or handles logins or payment. Paid apps are refused by default.

🛡️ No elevation

doctor prints fix commands, it never runs them. No telemetry, ever.
